# FlowLoad — память проекта

Актуальное состояние локальной утилиты нагрузочного тестирования на k6.
Этот документ предназначен для коллег и дальнейшей разработки. Секреты, реальные токены и результаты production-тестов сюда не добавляем.

## Первый запуск на macOS

```bash
git clone https://github.com/Danil63/FlowLoad.git
cd FlowLoad
make start
```

`make start` проверяет инструменты macOS, устанавливает отсутствующие Homebrew, k6 и Node.js, выполняет установку зависимостей UI и запускает локальный веб. Если требуется установка Apple Command Line Tools, закончите её и повторите команду.

Для последующих запусков: `make web` (синоним `make ui`). Эта команда не устанавливает зависимости: ошибка `Cannot find package 'yaml'` после клонирования означает, что сначала нужен `make start`.

Адрес: `http://127.0.0.1:8787/`. Интерфейс открывается со страницы «Окружение»; прямые ссылки на другие страницы сохраняются. Открывать `ui/public/index.html` как файл нельзя: приложению нужен локальный сервер.

Если порт занят, откройте уже работающий FlowLoad или остановите предыдущий процесс через Ctrl+C в его терминале. Другой порт: `UI_PORT=8790 make web`. Не завершайте неизвестные процессы. После закрытия последних подключённых вкладок сервер автоматически завершает работу, если нет активного теста.

## Окружение

Первая кнопка слева открывает список созданных окружений. «Создать окружение» задаёт имя и базовый URL API, «Настройки» меняют выбранное окружение. Активный проект выделен в списке.

У каждого окружения собственные токены, документы Swagger, методы, сценарии, профили нагрузки, отчёты и браузерные черновики. Переключение перезагружает страницу с параметром `workspace`; вкладки разных окружений можно держать открытыми одновременно. На одном локальном генераторе разрешён только один тест одновременно.

Из веба тест получает URL и файл токенов выбранного окружения. Терминальные команды используют настройки Makefile и не выбирают окружение автоматически.

## Токены

1. Ручной ввод добавляет токен к текущему набору без дублей.
2. Импорт `.txt` до 1 МБ заменяет набор. Один токен на строку; пустые строки, комментарии с `#` и повторы пропускаются. Не добавляйте имя cookie, Bearer, кавычки и точку с запятой.
3. Кнопка информации объясняет формат файла. Счётчик показывает количество сохранённых токенов, а не подтверждение их валидности.
4. Кнопка удаления очищает текущий набор; без токенов она недоступна.
5. «Проверить все токены» запускается отдельно после сохранения. Проверяется весь набор последовательно. Автоперехода к сценариям нет.

После изменения набора предыдущий результат проверки сбрасывается. Во время нагрузки или проверки изменение токенов запрещено. Отклонённые с HTTP 401 токены отображаются в модальном окне красным, с номером и частично скрытым значением. Сетевой сбой или незавершённая проверка не означают, что токен невалиден.

Текущая проверка авторизации привязана к защищённым методам игрового API и cookie `__Secure-better-auth.session_token`. FlowLoad пока не определяет способ авторизации произвольного API автоматически. Токены сессий могут истекать. Несколько VUs с одним токеном — это несколько исполнителей под одним аккаунтом, а не разные пользователи.

## Сценарии

Загрузите Swagger/OpenAPI 2.0 или 3.x файлом JSON/YAML либо по публичной HTTP(S)-ссылке. Файл выбирается стандартным системным диалогом. Загрузка по ссылке выполняется с компьютера пользователя, без передачи его сессионных токенов серверу документации.

Для страницы Swagger UI `/docs` загрузчик пробует `/docs-json`. Это не универсальный парсер любого HTML-интерфейса документации. Для остальных случаев используйте прямой JSON/YAML. Ограничения загрузчика: 15 секунд, 5 МБ, до пяти перенаправлений, только публичные IPv4-адреса. Если VPN/DNS возвращает непубличный адрес, запрос блокируется; используйте файл или исправьте сеть. Защита от обращения к локальной сети не отключается.

Загруженные документы перечислены в dropdown. Можно удалить документ со всеми методами или отдельный метод крестиком после подтверждения. Зависящие от удалённых методов сценарии и профили помечаются невалидными и не допускаются к запуску. Повторный импорт документа не восстанавливает старые ссылки автоматически.

В нижней полке доступны поиск и выбор методов. Метод можно добавить кнопкой, связать два выбранных метода или перетащить карточку. Между шагами есть стрелки вставки: над стрелкой копия карточки уменьшается до 30%, стрелка подсвечивается фиолетовым; отпускание вставляет шаг между соседями. Перенос внутри сценария перемещает шаг, а не создаёт дубль. Escape, отмена жеста и отпускание вне конструктора отменяют перенос. Поддержаны горизонтальная прокрутка и способ «выбрать карточку → нажать стрелку».

Dropdown «Сценарии» открывает сохранённые сценарии текущего окружения для редактирования. Сохраните результат под нужным именем; другое имя позволяет создать отдельный сценарий. Сохранённые сценарии можно удалить.

Сохранение и удаление сценариев/профилей проверяют исходную версию файла. Если файл изменён в другой вкладке, сервер возвращает 409, не перезаписывая его. При сохранении появляется окно конфликта: можно продолжить редактирование или сохранить копию под новым именем. Удалённый файл не восстанавливается устаревшим сохранением автоматически. Файл с уже занятым именем также нельзя молча заменить. После обновления приложения перезагрузите старые вкладки; старый черновик без версии нужно сохранить под новым именем либо заново открыть актуальный файл.

«Критический путь» — шаблон открытия конкретной игры, не универсальное определение бизнес-критичности. Он выбирает доступные GET-методы: `/profile`, `/aircraft`, `/routes`, `/routes/map`, `/quests`, `/carousel`, `/shop`, `/raffles/me`. Первые три обязательны. Перед заменой непустого сценария появляется подтверждение. Вход через Яндекс, полёт, покупки и получение наград сюда не входят.

## Нагрузка

В конструкторе выбирается ранее сохранённый сценарий. На графике отображаются его методы. Количество VUs меняется перетаскиванием точки или числом в поле карточки. Шкала до 1500 VUs; её отметки кликабельны и устанавливают одинаковое значение всем методам. Ручной ввод допускает значение выше визуальной шкалы в пределах проверки приложения. Профиль нужно сохранить.

Под конструктором находится «Запуск». Список содержит пользовательские сценарии и профили, а не встроенные пресеты. Кнопка информации справа от «Запустить» открывает объяснение k6 и диаграмму разгона, удержания и снижения нагрузки.

Два разных режима:

| Режим | Что делает один VU | Как считается нагрузка |
| --- | --- | --- |
| Сценарий | Проходит методы последовательно, делает паузу и повторяет цепочку | Поле «Пользователи» задаёт целевое число VUs для всей цепочки |
| Профиль нагрузки | Повторяет один метод в отдельном сценарии k6 | VUs всех методов суммируются; 20 + 30 дают целевой максимум 50 |

График распределения по методам не является временной последовательностью запросов. Профиль не заменяет связанный бизнес-сценарий.

Используется `ramping-vus`. Через Makefile по умолчанию: `RAMP_UP=1m`, `HOLD=3m`, `RAMP_DOWN=30s`, `THINK_TIME_SECONDS=1`. Значения можно переопределить в окружении запуска. При прямом запуске пользовательских скриптов без Makefile их временные значения по умолчанию отличаются: 10/30/10 секунд. Завершение текущих итераций может продлить общее время.

VU не равен RPS: запросов в секунду будет меньше при долгих ответах или больших паузах. API-нагрузка создаётся компьютером, на котором запущен локальный сервер/k6, а не вкладкой браузера.

## Ограничения и безопасность

- Swagger описывает контракт, но не гарантирует бизнес-логику, зависимости данных и правильные тестовые значения.
- Изменяющие данные методы по умолчанию пропускаются без `ENABLE_STATE_CHANGING=true`. Успешный пропуск не доказывает работоспособность операции.
- Параметры путей и тела запросов требуют подготовки; шаблонные значения не подходят для production-покупок или полётов.
- Сгенерированный сценарий не добавляет автоматически извлечение ID из ответов и передачу их следующим шагам.
- Начинайте с малой нагрузки и тестовых аккаунтов. Рост ошибок, 429/5xx, резкое ухудшение p95/p99 или нарушение состояния — повод остановиться и исследовать причину. Автоматическая остановка по всем этим признакам не реализована.
- Нагрузка может упираться в клиентский компьютер, сеть, приложение или БД. Один клиентский отчёт не доказывает, что инфраструктура слабая.

## Отчёты и метрики

Отчёты HTML на русском сохраняются локально; UI показывает отчёты выбранного окружения. Makefile открывает отчёт после теста, в том числе после проваленных порогов. `OPEN_REPORT=false` отключает автоматическое открытие.

| Метрика | Значение |
| --- | --- |
| VUs | Виртуальные исполнители, работающие параллельно |
| Итерации | Завершённые повторения функции сценария |
| RPS | Число HTTP-запросов в секунду |
| Avg / Med | Среднее время / медиана |
| p95 / p99 | Время, не превышенное примерно 95% / 99% запросов |
| Max | Максимальное наблюдавшееся время |
| http_req_failed | Доля запросов, признанных k6 неуспешными |
| checks | Доля успешных проверок, заданных скриптом |
| thresholds | Пороговые условия прохождения теста |

`Error 99` означает провал порогов k6, а не ошибку Makefile. HTTP 401 указывает на непринятую авторизацию; 403 может означать отсутствие прав; 429 — ограничение частоты. Нулевые HTTP-ошибки не гарантируют правильность бизнес-логики, а JSON с сообщением ошибки может пройти проверку «есть тело ответа».

## Локальное хранение

| Данные | Где хранятся |
| --- | --- |
| Реестр окружений | `ui/.local/workspaces/index.json` |
| Данные новых окружений | `ui/.local/workspaces/<id>/` |
| Токены основного окружения | `load-testing/k6/tokens.txt` |
| Каталог основного окружения | `ui/.local/swagger-catalog.json` |
| Сценарии основного окружения | `load-testing/routes/local/` |
| Профили основного окружения | `load-testing/load-profiles/local/` |
| Отчёты основного окружения | `load-testing/k6/results/` |
| Рабочие черновики | sessionStorage каждой вкладки, отдельные ключи на окружение |
| Последняя резервная копия черновика | localStorage браузера, отдельные ключи на окружение |

Все перечисленные файлы данных исключены из Git. Токены хранятся локально с ограниченными правами доступа, но не зашифрованы. Старые ключи браузерных черновиков мигрируют на ключи FlowLoad; смена порта или браузера меняет доступное localStorage. Для проверки чистого онбординга используйте инкогнито и новую копию проекта.

## Команды и проверка разработки

Инженерный аудит и оставшиеся ограничения: [ENGINEERING_REVIEW.md](./ENGINEERING_REVIEW.md). Каталог проверяется по действующим ID и журналу удалений; сценарии/профили сохраняются атомарно. HTTP-кеш API/UI отключён, вкладки обновляют данные при возвращении фокуса. Изменения данных запрещены во время теста.

Одна папка проекта допускает только один сервер: `proper-lockfile` хранит блокировку в `ui/.local/server.lock`, независимо от выбранного порта. При обновлении остановите старые процессы и запустите новую версию. Обычное завершение снимает блокировку; после аварии требуется до 30 секунд. SIGINT/SIGTERM ожидают активный тест и записи. Блокировка не останавливает осиротевший k6 после SIGKILL и не защищает от ручного изменения файлов.

Повреждённый сценарий или профиль не скрывает исправные записи: он отмечается красным с диагностикой; открыть или запустить его нельзя, удаление доступно. Сервер также проверяет структуру файла перед запуском.

### Восстановление каталога и окружений

Каталог Swagger и реестр окружений проверяются при чтении: структура JSON, уникальность ID, принадлежность методов документам и целостность журнала удалений. Рядом с файлом при изменении создаётся `<имя>.recovery.json` с контрольной суммой SHA-256 и привязкой к окружению. Чтения и записи одной пары файлов выполняются последовательно, без долгоживущего кеша.

Сначала атомарно записывается копия новой версии, затем основной файл. Если процесс прервётся между ними, FlowLoad не выбирает старую версию автоматически: возвращает 503 `STORAGE_RECOVERY_REQUIRED`. Восстановление применяет последнюю подготовленную запись, даже если исходное сохранение не успело завершиться. Поэтому прерванное удаление не откатывается к старому каталогу. ID и журнал удалений сохраняются; повторно разрешать зависимые сценарии нельзя.

Повреждённый или отсутствующий основной файл при наличии копии не заменяется пустым. Повреждение каталога блокирует работу с его сценариями и профилями, но не исправные окружения. При повреждении реестра веб остаётся доступен с диагностикой; список окружений показывает недоступность, а не бесконечную загрузку. Изменения и запуски не проходят проверку реестра.

Команды выполняются из папки проекта после остановки веба через Ctrl+C. Они используют ту же блокировку, что сервер, и не запускают k6:

```bash
make storage-check
make storage-backup
make storage-recover STORE=workspaces
make storage-recover STORE=workspaces CONFIRM=1
make storage-recover STORE=catalog WORKSPACE=default CONFIRM=1
```

`storage-check` диагностирует реестр и каталоги всех зарегистрированных окружений. `storage-backup` защищает существующие исправные файлы старой версии, у которых ещё нет копии; повреждённые файлы и несовпадающие пары не перезаписывает. До первого изменения или этой команды старый файл может оставаться без копии. Пустое новое хранилище не требует восстановления.

Для именованного окружения вместо `default` укажите его ID из параметра `workspace` в URL. Без `CONFIRM=1` команда восстановления показывает состояние и ничего не заменяет. Сначала восстанавливайте реестр, затем нужный каталог. Перед заменой основной файл побайтово сохраняется рядом как `.damaged-<время>-<id>` с правами 0600. Токены, сценарии, профили, отчёты и другие окружения не изменяются.

Если копии нет или она повреждена, восстановление отказывается менять данные. Копия локальная, не зашифрована и исключена из Git вместе с `ui/.local/`; это не внешний бэкап и не архив всех версий. Одновременная потеря основного файла и копии, ручная подмена обоих файлов, сбой диска или питания этой защитой не покрываются. Не удаляйте копии вручную и не используйте старую версию сервера после миграции без проверки. Восстановленные файлы проверяются повторно при следующем чтении.

Черновики сохраняются с задержкой 250 мс и при уходе со страницы/смене окружения. Одинаковые снимки не записываются повторно. Каждая открытая вкладка восстанавливает свою рабочую копию вместе с исходной ревизией; новая вкладка без своей копии использует последнюю общую резервную копию. Закрытие вкладки не создаёт архив всех её версий. При запрете sessionStorage полной изоляции черновиков нет. После миграции каталог Swagger хранится только на сервере, а не в каждом черновике. При переполнении или недоступности браузерного хранилища появляется предупреждение; сохранённые серверные сценарии не удаляются.

Ревизия файлов вычисляется как SHA-256 содержимого, формат сценариев и профилей на диске не изменён. API возвращает `revision` при чтении и в списках; для изменения или удаления нужно передавать `baseRevision`. Очередь сервера объединяет проверку версии с записью/удалением. Редактор не обновляет свою исходную ревизию из фонового обновления списков. Прямое редактирование файлов сторонними программами не синхронизируется с очередью FlowLoad.

История сервера в памяти ограничена 30 запусками; завершённые записи старше часа удаляются при очередной очистке. Активный запуск и HTML-отчёты на диске не удаляются. Неограниченный объём результатов одного большого файла токенов пока остаётся отдельным риском.

```bash
make start       # Установка зависимостей и запуск веба
make web         # Повторный запуск веба
make check       # Проверка k6
make help        # Полный список целей Makefile
node --test ui/*.test.mjs
```

В репозитории сохранены специализированные CLI-сценарии игрового API (`make ping`, `make public 10`, `make auth 5`, `make auth-status`, `make flight-once`, `make browser`) и распределённые запуски. Это не универсальные пресеты для любого окружения; проверяйте URL, токены и сценарий до запуска. `make auth-status 120` не создаёт нагрузку на 120 пользователей.

Проверки UI и серверных API выполняйте на временных данных, не меняя пользовательские токены и не создавая production-нагрузку. При изменениях обновляйте этот документ. Название продукта — FlowLoad; реальные адреса внешних API не переименовываются. Старые имена допустимы только в коде миграции данных.

Дополнительные конфигурации наблюдаемости находятся в `observability/` и `render.yaml`, не требуются для локальной работы и не разворачиваются автоматически. После переименования ресурсов нельзя синхронизировать существующее облачное окружение без проверки плана изменений; ранее собранные метрики со старыми метками не переименовываются задним числом.
